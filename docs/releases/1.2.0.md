Hexlora 1.2.0 is a stability and robustness release, hardened against very large, damaged and hostile inputs.

**Stability**
- Fixed a desktop crash when opening a property list nested tens of thousands of levels deep.
- Archives with very many members no longer hang: a 200,000-entry ZIP now opens in about a second.
- Opening a large file no longer reads all of it into memory.
- Pipes, sockets and device files inside a folder are skipped instead of risking a hang.

**Opens more, fails less**
- Damaged or truncated ZIP files open as ordinary files, with Hex, strings and hashes available and the reason shown.
- ZIP bombs and archives with unsafe, over-deep or duplicate member paths open normally. Problem members are flagged or hidden and counted in Details; bomb-like members are listed but never decompressed.
- One unreadable file no longer prevents a whole folder from opening.
- Folders and archives beyond 200,000 entries are listed up to the limit with a note instead of being refused.

**Faster**
- CLI reports for large folders are written up to 30 times faster.
- Large JSON files are parsed far more quickly.
- Entropy profiles of compressed archive members are sampled in one pass.

**Usability**
- The entropy heatmap shows near-constant data in grey rather than the caution colour.
- Typing a `0x` offset no longer empties the Artifact Tree.
- Jump Offset, Find Next and Copy Hex explain what is wrong when the offset is out of range or no file is selected.
- `hexlora-cli --output /dev/null` works, and Markdown and HTML reports are now written atomically.

**Behaviour change for CI**
- Damaged or hostile archives used to end `hexlora-cli inspect` with exit status `1`. They now produce a report, marked partial (exit status `5`) when anything had to be skipped. Use `--fail-on` or a release policy to gate on them.
