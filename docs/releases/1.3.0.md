Hexlora 1.3.0 adds binary triage: readable symbols, inferred capabilities, your own YARA rules, debug symbols, and a bounded disassembly preview — enough to decide what deserves a dedicated reverse-engineering tool, still without running anything.

**Disassembly**
- A new **Disassembly** tab lists the functions Hexlora can find in a PE, ELF, or Mach-O binary (x86, x86-64, arm64) and shows a linear listing with call targets, imports, and referenced strings named.
- Click a function to list it; click a line to follow its target or see its bytes in Hex. Symbols and Exports rows gain a **Disassemble** action.
- A PDB, dSYM, or `.debug` file beside the binary is used automatically when it matches, adding function names and source lines. **Load Symbols…** picks another. Nothing is downloaded.
- External tools launched from the tab are handed the address you are reading: radare2 opens at it, IDA jumps to it, objdump disassembles just that code. For tools with no address option the address is copied to the clipboard.
- `hexlora-cli disasm` prints the same listings as text or JSON.
- The listing is deliberately linear. Hexlora does not follow indirect jumps, rebuild control flow, or decompile.

**Capabilities**
- A new **Capabilities** tab shows what a binary appears able to do — inject into other processes, persist, capture input, use the network, map physical memory from a driver — with the imports and strings behind each inference and a confidence.
- Policies can forbid capabilities with `forbidden_capabilities`, by identifier or by group such as `injection.*`.

**YARA**
- **File → Scan with YARA Rules** (`⇧⌘Y`) scans every file in the artifact, archive members included, with a rule file or folder you choose, and lists the matches in a YARA tab. `hexlora-cli inspect --yara <rules>` does the same in CI.
- Hexlora ships no rules and downloads none.

**Windows binaries**
- Import hash (imphash), Rich header, overlay detection, and packing traits such as an entry point outside the code section or packer section names.
- Kernel drivers are identified, with their driver model and whether they expose a device to user mode.

**Easier to read**
- C++, Rust, and MSVC symbol names are shown demangled beside their mangled spelling, and search matches either.
- Findings show a stable rule ID and, where they are an inference, a confidence. SARIF output carries the rule ID.

**Fixes**
- A Mach-O file with a looping export table no longer crashes Hexlora.
- A Mach-O file with a damaged symbol count no longer stalls analysis.

**Upgrading**
- `inspect` now reports capability and packing findings by default, up to medium severity. A pipeline using `--fail-on medium` or an equivalent policy may start failing on a binary that, for example, imports the full process-injection sequence. Silence a specific finding with `disabled_rules` and its rule ID.
- New report fields are additive; the schema version is unchanged.
